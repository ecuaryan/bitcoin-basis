# Design system (app/)

For agents building the remaining screens. The approved mockups are the source of truth; this file says how to build them with the pieces that exist. Tokens live in `app/src/styles.css` (`@theme`), components in `app/src/ui/`.

## Rules

1. Bitcoin orange `#F7931A` is the only accent. Amber `#FFB547` only for the gradient end, hover and active nav text. No other hues, with two exceptions for data: gains (and other good-news money: "left over", a price above your average, the 24-hour "up" arrow) are green (`gain`), so they never read like the orange accent or the red loss; and documentation tiers use orange, cream, tan, grey (see below), and retirement Bitcoin is a soft slate blue (`retire`), the one cool colour, so it never reads as a tier. Never use `retire` for buttons, links, text or anything but marking retirement Bitcoin.
2. Every number is tabular (`font-variant-numeric: tabular-nums` is set globally). Big numbers use `font-display` (Space Grotesk); everything else Inter.
3. Money is cents, BTC is sats, integers only. Format with `lib/format.ts`; show them with `<Money>` and `<Amount>` so hide-amounts works. Never print a raw number that is the user's money.
4. Whole-dollar display rounds toward zero (never overstates a gain); an amount under $1 that is not $0 keeps its cents (`+$0.40`, never `+$0` or `down $0`). Where whole-dollar parts sit under a whole-dollar total (the Taxable and Retirement rows under the hero, the Retirement card's wallets), the parts use `wholeDollarParts` (largest remainder) so they add up to it; the taxable Unrealized gain shows the Taxable row's figure (`view.split`, `taxableGainShownCents`). The Holdings loan lines show cents, like the loan page. Coins are valued lot by lot everywhere (`valueOfPieces`). A short BTC amount (`short`, 4 decimals) too small to show keeps all 8 (`0.0000 4999`), never `0.0000`. A short BTC figure that must not look better than it is rounds one way (`Amount round="up"` for a shortfall, `"down"` for a leftover; USD to the cent the same way; sats exact).
5. Hide amounts is OFF by default; only the user turns it on (the choice is remembered on that device). Anything showing the user's balances, cost, gain or income must go through `Money`/`Amount` (or `maskDigits`). Market price is public and may be shown plainly.
6. Motion: only CSS (`animate-*` tokens) or `useCountUp`; both honor `prefers-reduced-motion` (CSS has a global override, the hook jumps to the end value). No animation libraries.
7. Touch targets 44px (`min-h-11`); dense list rows at least 24px. Interactive elements never nest (no `Amount` button inside a link: use `interactive={false}`).
8. Plain language, no jargon, no emoji. Estimates are labeled as estimates.
9. CSP is strict (`style-src 'self'`): use classes, not `style=` attributes in markup strings. React `style={{}}` props are fine (set through the DOM, not as attributes). No inline scripts, no remote fonts or images.
10. Keep axe at zero violations (`npm run e2e -w @bitcoin-basis/app`). A visible label must appear inside the accessible name.
11. Percent shares: risk warnings round up (`riskPercentFromBp`: 19.99% is 20%); documentation tiers use `sharePercents` (largest remainder, adds up to 100%, 100% only for all of it, `under 1%` for a sliver); the price change is the past 24 hours (`in 24h`), half away from zero, with no arrow or color at 0.0%. Hide amounts masks every personal percent (gains, break-even distance), keeping its width.

## Layout

- Phone (< 1024px): header (brand, hide, lock), scrolling `main` (20px side padding), fixed bottom nav 92px with 4 tabs and the orange + between them: Holdings, What if, + (opens the Log sheet), Tax, Records. Tabs are top-level screens, so they have no back arrow. Column is max 560px, centered.
- Desktop (>= 1024px): 220px sidebar (Holdings, What if, Tax season, Records, orange Log button), main padded 32/40. The screen draws its own Hide amounts / Lock text buttons in its header.
- Screens choose layout with `useIsWide()` (a media query hook), not by rendering both. Use `useLogSheet().open()` to open the Log sheet.
- Routes: `/` Holdings, `/what-if`, `/records`, `/tax`, `/wallet/:id`, `/loans/:id`, `/log` (opens the sheet), plus full-screen `/welcome`, `/unlock`, `/kit`. Add real screens by replacing the stub in `screens/stubs.tsx` and the element in `App.tsx`.

## Components (`app/src/ui/`)

- `AppShell`: the frame (`<Outlet/>` inside). Also exports `HideButton`, `LockButton`, `Brand`, `useIsWide`, `useLogSheet`.
- `Sheet({ open, onClose, title })`: slide-up modal (centered panel at >= 640px). Focus moves in, Tab wraps, Esc/backdrop/close button close, focus returns to the opener, `#root` is inert while open. Use for every modal.
- `Button` (`primary` orange, `secondary` bordered, `ghost`) and `buttonClasses()` for links styled as buttons. One primary per screen.
- `Card`, `Stat`: standard surface and label/value pair.
- `Segmented`: radio-group segmented control with arrow keys (Sell/Borrow, ranges).
- `Amount({ sats, showUnit, short, interactive, countUp })`: BTC with 8 decimals grouped `0.0074 2665`; tap cycles BTC, sats, USD (global choice, saved). `short` = 4 decimals for lists; `alwaysBtc` keeps BTC whatever unit was picked (the Holdings split rows, where the dollars sit beside it).
- `Money({ cents, precision: 'cents'|'dollars', signed, countUp })`: `$1,234.56`.
- `PriceChart`: hand-rolled SVG price line with dashed average-cost line and orange gap fill. Holdings draws it from one point per day (`/api/price/series`, three years, kept an hour in `bb.price-series.v1`; a server without it falls back to quarterly `/api/price/history` lookups). A daily line is smoothed to about one point per 2.5 viewBox units (`ui/chart-line.ts`) with the highest day kept exactly and marked (`markHigh`): an amber dot and `High $126,073 · Oct 6, 2025` (dollars masked by Hide amounts; hidden while scrubbing). Scrubbing (`ui/chart-scrub.ts`) steps through every day (arrows, Page Up/Down about a month, Home/End); the dot sits on the drawn line, the label gives that day's price. The screen-reader table lists the first day of each month, the high and today.
- `useCountUp`, `useMediaQuery` (`motion.ts`); `Toast` (`useToast().show(msg)`, polite live region; just below the header on a phone, bottom right on desktop, never over the brand).
- `PriceFreshness.tsx`: `PriceRefreshButton` (a 16px `RefreshIcon` beside the Holdings price, muted, 44px hit area from padding and an equal negative margin, `aria-label="Refresh the price"`, spins while loading; calls `refresh()`) and `PriceAge` (`· as of 3:12 PM` after a live price older than 5 minutes or sent `stale` by the server; amber past 30 minutes; nothing for a current, demo or typed price). If the price shown is not current, its time says so; a failed refresh never turns a shown price into an error.
- `PriceProblem.tsx`: when the live price cannot be loaded, `PriceUnavailable` (a card: "Can’t load today’s Bitcoin price.", what this screen needs it for, Retry, "Use a price I enter") or `PriceUnavailableLine` (the Holdings hero). A typed price is session-only, shown as "Using your price $X" wherever it is used (the `ManualPriceBanner` on every screen), and saved only inside an entry the person saves (its note says "your price").
- Hide amounts: `usePrefs()` gives `hidden`, `masked`, `toggleHidden`. Holding any masked amount (pointer or Space/Enter) or the eye button shows everything until release. A hidden amount is always one fixed shape (`$•••••`, `•.•••• ••••`; `maskDigits`), so its length never hints at its size.
- `SectionHeader` (`ui/SectionHeader.tsx`): the one section header. Title left (with its "?" right after the words), a count (`SectionCount`, e.g. `9 entries`) or one action (`SectionLink`, e.g. `All 9 entries`) right. Under a shortened list, `ShowMore` (quiet button, left): `Show all 12 entries`. Empty lists use `EmptyLine`.
- **Entry lists** (`EntryTable`, `screens/entry-table.tsx`; words and figures from `rowLine` in `lib/entry-row.ts`, on top of `describeEntry`): every list of entries (Records' recent and all entries, a wallet's entries) comes from `entryRows` in `lib/entry-list.ts` and renders `EntryTable`; tapping a row opens `EntrySheet` (details, history, `Edit purchase` / `Remove this purchase`). The box is a container. Under 34rem of card (every phone) a row is the glyph, the title with its tags over `wallet · note · date` (with the year), and the signed 8-decimal BTC over its dollars and what they were (`$680.00 paid`; a move's `fee 0.0000 1840`; a loan record's dollars over `paid`). From 34rem it is one grid, each row a subgrid: Date (month and day over the year) · What (glyph; title, tags and the muted note: income or spending description, loss cause, import origin, a loan record's loan) · Wallet (`Strike → Cold card` for a move; `—` for loan, settings and year records; dropped on a wallet's own page) · Bitcoin (`Amount` without `short`, `alwaysBtc`, signed `+`/`−`, an unsigned figure keeps an invisible `+` so digits align; a move's fee under it) · Dollars (`$680.00` over `paid`, `received` or `worth then`; `—` when none). On a wallet's own page the figures are that wallet's: a move out is `Moved to …` with what left (`sats + feeSats`, signed −) and `… arrived · fee …` as its note, a move in is `Moved from …` (+ what arrived), so the signed rows add up to the wallet's balance (a unit test checks the demo book). Column headings are visual only (`aria-hidden`); DOM order is the reading order (title first) and each cell carries screen-reader commas and words (`BTC`, `fee`, `no Bitcoin`, `no dollars`), so a row reads "Bought, Strike · Nov 18, 2026, +0.0074 2665 BTC, $680.00 paid". Settings changes are hidden unless filtered for, balance confirmations are never listed (they show as `Confirmed Nov 21` on the wallet), and every count is the number of rows shown. Strikethrough means removed and always comes with a `Removed` badge (its amounts muted); `Edited` appears only for the person's own edits; tags: `Needs a decision`, `Removed`, `Edited`, the loan badge, `Retirement`.
- Loans (`screens/loans/`): Holdings shows a Loans section only when a loan is open; every figure comes from the engine (`loanSummary`, `loanPurchases`, `suggestLoanPayment`). Estimates carry a quiet `≈` (`Approx`) and the section's "?" says what is estimated. Loan-funded purchases show `LoanBadge` (`HELOC` or `Loan`) wherever a purchase or its lots are listed. The loan page shows `Bought` (everything the purchases bought, `boughtSats`) and, when some has left or is frozen, `Still held` with a muted note naming how the rest left (`goneWords`: `0.0037 6981 BTC later given away, sold, spent or paid as network fees`, only the ways that apply, most first). The break-even and payoff "?" say they use the Bitcoin still held, and whether unbilled interest is in them (payoff: yes, as an estimate; break-even: interest paid so far only). Loan records stay out of entry lists unless Kind = Loan.
- Tax estimates: until filing status, state and income have been saved once, `TaxProfilePrompt` asks for the missing ones; while income was never saved, every tax estimate (Tax season, Sell, Borrow, Log review) shows `NoIncomeNote` ("Assumes $0 other income. Set your income in Settings."). A saved $0 is an answer.
- Retirement wallets: the wallet page lists purchases with cost, worth now and gain (`retirementPurchases`); `useLogSheet().open({ kind: 'retirement-buy', wallet })` opens the purchase form on its own (no tab), and edits and removals use the usual `EntrySheet` flow. When a retirement wallet holds coins, the Holdings hero is all your Bitcoin (`heroFigures`: "All your Bitcoin is worth", total BTC, then `HeroGainLine`, "up $… (+…%) unrealized", "Average cost of all your Bitcoin: $… per BTC"), all from the engine's `allBitcoin`. Under it `SplitCard`: a thin bar (taxable orange, retirement `retire` blue, by BTC) and two rows, Taxable (jumps to the taxable figures) and Retirement (opens the one retirement wallet, or jumps to the Retirement card when there are several); on desktop the rows sit side by side and show the gain percent. **One order on phone and desktop, most looked-at first**: hero (worth and gain), nudges (balance check, loan payment), `RecentPurchases` ("Recent purchases"), Loans (above or below break-even), `SplitCard`, `TaxableFigures` (`id="taxable"`, the Taxable row's jump target: unrealized gain, taxable average cost, losses from past years), Wallets (frozen wallets listed last, amount muted, "Frozen, not counted"), then the look-back cards: `StackCard` ("Your stack, by year bought"), `AverageChartCard` ("Price vs. your average cost"), `RetirementCard` ("Retirement": each retirement account's BTC, worth, cost and gain; "Cost not logged" with balance notes only) and "How well it is documented". There is no separate Taxable heading: each taxable card says it is taxable. Desktop pairs Wallets (two thirds) with documentation, and the chart with the Retirement card. The chart's switch (`Segmented`, "Average cost line for") picks whose average the dashed line is: All (default), Taxable or Retirement (`averageLines(view)`; a line shows only when every coin in it has a known cost, and the switch only with two or more); the line under the chart names it ("Average cost of all your Bitcoin: $…"). The last choice is kept while the app is open. Without retirement coins there is no split or switch, and the hero is the taxable total ("Your Bitcoin is worth"). The taxable cards never include retirement coins. **Stack by year** (`StackCard`, phone rows `StackRows`, desktop columns `StackColumns`; `view.stack` from `lib/holdings-view.ts`): each year is the taxable lots (wallets not frozen, by tier) plus the retirement purchases bought that year (by purchase date, one `retire` segment after the tiers), so the years add up to the hero's BTC. The legend lists the tiers present, then Retirement; the line under the card gives the documented share of the taxable lots ("Taxable: 94% documented." with retirement, "94% documented." without). The year sheet (`YearSheet`, `row.pieces`) lists lots and retirement purchases together, newest first; a retirement purchase shows the `retire` bar, "Retirement" where a lot shows its tier, worth and gain, and opens to where it came from, cost and receipt (no tier). A gain not yet taken is called "unrealized" (never "on paper").
- Icons (`ui/icons.tsx` for navigation and sections, `ui/more-icons.tsx` for actions, `ui/auth-icons.tsx`): 24px viewBox, round strokes, always `aria-hidden` beside a visible label. - **Gifts (the Gave tab).** The lot picker (`CoinPicker`, `auto="lowest-cost"`) starts on "Lowest cost first" for a gift (sales, moves and losses: "Oldest first"); the reason sits once under the choice (`LOWEST_COST_WHY`), the automatic list shows the lots in the order they are used, and an amber one-liner appears only when part of the gift comes from lots that cost more than they were worth that day ("… Nobody can claim the loss on that part."). "I bought it to give" is a `Toggle` in a bordered row under "Who it went to"; it starts on when the last gift was logged that way (`lastGiftWasBoughtToGive`). On, the form (`BuyToGive.tsx`) shows "What you bought" (amount, Bought in, total paid with fees, when) then "The gift" (who, a plain summary line "Gives all of it, 0.0005 2734 BTC, worth $50.00 (what you paid), right after the purchase."), with Amount given and Worth that day under More details. Its review uses `Draft.groups` (Purchase, Gift: small uppercase headings over two summary cards) and one Save. The switch and "Who it went to" stay mounted when it flips, so focus stays put. Entry rows read "Gave to Mom" over "Strike · Nov 21, 2026".
- **Scroll and Back.** `useScrollBehavior` (`ui/scroll-behavior.ts`, in `App.tsx`): a new page starts at the top, tabs keep their own place, tapping the current tab goes to the top, Back/Forward restore each history entry's place (waiting up to 1.5 s for the page to be tall enough), and a link with a hash (`/settings#taxes`) lands on its section. In-app back buttons are `BackLink` (`ui/BackLink.tsx`): history back when the app brought you there (labelled "Back"), else a link to the fallback ("Back to Holdings").
- Field errors use `ErrorLine` (built into every field): once shown, its line stays reserved after the fix so the form does not jump. One back button style (44px, `rounded-xl`, `ChevronLeftIcon`); in a pair of buttons the cancel comes first and the primary last.

Documentation tiers (`TIER_BG`, `TIER_LABEL` in `screens/holdings-parts.tsx` and `lib/origin.ts`): Documented orange, Reconstructed cream, Estimated tan, Unknown grey. Always show the tier by color plus text.

## Data

- `useLedger()` (`data/ledger-provider.tsx`): `entries`, replayed `state`, `holdings`, `append(entries)`, `isDemo`, `today`. Build screen numbers from engine output (see `lib/holdings-view.ts`), never re-derive money in components.
- `usePrice()` (`data/price-provider.tsx`): `quote` (cents per BTC, null until known; `asOf` when the price is from, `stale` when the server sent a kept price, `provider`; `source: 'manual'` while a typed price is in use), `status` (of the live price: `error` means the last try failed, and a quote may still be there: show it, with `PriceAge`, and treat `error` as a problem only when `quote` is null), `error`, `refresh()`, `manualCents` / `setManualCents()`. After a failure it tries again after 15 s, 30 s, 60 s, then every minute. Live from mempool.space through the Worker (Coinbase when mempool fails); the demo book uses a fixed price; the test build's fake server answers `/api/price`, `/api/price/history` and `/api/price/series` with fixed prices (the series follows the demo chart's made-up days, `demoDailyPrice`) (fail them with `window.__bbFake.server.failing.set('/api/price', 503)`; answer a kept, stale price with `window.__bbFake.server.priceKeptAt = <ms>`).
- Demo book: `demo/demo-data.ts` (`buildDemoBook()`); synthetic only.
